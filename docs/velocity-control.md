# OpenRB-150 두 모터 속도 제어 실습

[프로젝트 README](../README.md) · [2026-10-31 실습 결과](2026-10-31-velocity-test.md)

실행 코드: [two_motor_velocity_test.ino](../firmware/two_motor_velocity_test/two_motor_velocity_test.ino)

대상: OpenRB-150 한 개 + XL330-M288-T 두 개. 기존 ID `1`, `2`, 모터 통신 속도 `57600bps`, Protocol 2.0을 유지합니다. 시리얼 모니터는 `115200 baud`입니다.

## 준비

1. 처음에는 바퀴나 부하를 달지 않고 모터 본체를 안정되게 고정합니다. 회전축은 막지 않습니다.
2. 기존 위치 제어 스케치는 별도 파일로 보관합니다.
3. `two_motor_velocity_test` 폴더 안의 같은 이름 `.ino` 파일을 Arduino IDE에서 엽니다.
4. 보드를 OpenRB-150, 포트를 연결된 보드로 선택하고 업로드합니다. Dynamixel2Arduino가 필요합니다.
5. 시리얼 모니터를 115200 baud로 열고 `READY`를 확인합니다. 시작 시에는 움직이지 않습니다.

OpenRB-150의 USB 모터 전원 경로는 500mA로 제한됩니다. 두 모터에 부하를 걸거나 바닥에서 주행하기 전에는 XL330에 맞는 외부 5V 전원을 준비하고 보드 전원 점퍼를 확인합니다. 소프트웨어의 출력·전류 감시는 USB 전원 용량을 보장하거나 전원을 물리적으로 차단하는 장치가 아닙니다.

## 1단계: 모터별 양방향 회전

한 번에 문자 하나를 입력하고 Enter를 눌러 전송합니다. 줄바꿈 설정은 어떤 것을 선택해도 됩니다. 각 명령을 입력하고 약 2초 뒤 `AUTO_STOP`이 나올 때까지 기다립니다.

| 명령 | 대상과 동작 |
| --- | --- |
| `p` | 두 모터 모델·설정을 확인. 오류 해결 후 다시 준비 |
| `1` | ID 1 모터를 +방향으로 약 2초 |
| `2` | ID 2 모터를 +방향으로 약 2초 |
| `3` | ID 1 모터를 -방향으로 약 2초 |
| `4` | ID 2 모터를 -방향으로 약 2초 |
| `s` | 즉시 속도 0과 토크 해제를 요청 |
| `h` | 명령 안내 다시 보기 |

추천 순서: `p` → `1` → 자동 종료 → `3` → 자동 종료 → `2` → 자동 종료 → `4`.
`1`·`3`은 ID 1, `2`·`4`는 ID 2의 시험입니다.

목표는 약 8rpm입니다. 8rpm으로 정확히 2초 돌면 약 96도이므로, 여러 바퀴를 도는 시험은 아닙니다. 가속 시간과 낮은 출력 제한 때문에 실제 각도·속도는 달라질 수 있습니다. 반대 방향으로 움직이는지, 두 모터를 따로 선택할 수 있는지 확인합니다.

중단 시험: `1`을 보낸 직후 2초가 지나기 전에 `s`를 보내세요. `STOP: user command.`와 `TORQUE_OFF_CONFIRMED`를 확인합니다. 토크 해제는 구동력을 끄는 동작이므로 관성에 의한 물리적 즉시 정지나 바퀴 제동을 보장하지 않습니다.

## 2단계: 자동차 조작 명령 시험

ID 1을 왼쪽 모터, ID 2를 오른쪽 모터로 정했습니다. 바퀴 없이 축의 회전 조합부터 확인합니다.

| 명령 | 왼쪽 바퀴 역할 | 오른쪽 바퀴 역할 |
| --- | --- | --- |
| `w` | 앞으로 | 앞으로 |
| `x` | 뒤로 | 뒤로 |
| `a` | 구동 해제 | 앞으로 |
| `d` | 앞으로 | 구동 해제 |
| `s` | 속도 0·구동 해제 | 속도 0·구동 해제 |

모든 구동 명령에 같은 2초 자동 종료가 적용됩니다. `a`, `d`는 한 바퀴를 구동 해제하는 기초 회전 명령입니다. 움직이지 않는 바퀴를 능동적으로 고정하거나 정확한 회전각을 제어하지는 않습니다.

좌우 모터를 서로 반대 방향으로 장착하는 구성을 가정해 다음 값으로 작성했습니다.

```cpp
const int8_t LEFT_FORWARD_SIGN = +1;
const int8_t RIGHT_FORWARD_SIGN = -1;
```

아직 장착 방향은 확인되지 않았으므로, 이 설정만으로 실제 차체의 전진·좌우 회전을 확인했다고 볼 수는 없습니다. 조립 후 바퀴를 바닥에서 띄운 상태에서 한쪽씩 확인하고, 전진 방향이 반대인 쪽의 부호만 바꿉니다. 기본값에서 `w`를 보내면 **ID1 +방향, ID2 -방향**으로 동작합니다.

## 코드의 제한·중단 처리

- 목표 속도: raw 35, 약 8.0rpm. `SPEED_RAW`는 rpm 단위가 아닙니다.
- 출력: `GOAL_PWM`을 raw 120 이하, 약 13.6%로 제한합니다. 기존 EEPROM PWM 한계가 더 낮으면 그 값을 유지합니다.
- 전류: 약 100ms마다 모터당 200mA 이상 또는 합계 300mA 이상을 감지하면 정지를 요청하고 오류 상태로 잠급니다. 순간 피크를 막는 전류 조절기는 아닙니다.
- 통신: 모터의 Bus Watchdog을 500ms로 설정하고 주기적으로 상태를 읽습니다. 보드가 멈추어 모터에 명령 패킷이 끊기면 모터 측 정지 기능이 동작하도록 설정합니다. 실제 통신 단절 시험은 아직 하지 않았습니다.
- 정상 종료·중단·오류에서 모두 두 모터에 속도 0 및 토크 해제를 시도합니다. 토크 설정을 읽어 해제를 확인하지 못하면 `STOP_UNCONFIRMED`를 출력합니다. 이때 모터 전원을 분리하고 연결을 점검합니다.
- 동작 중에는 새 이동 명령을 무시합니다. 대기 후 새 명령을 입력하거나 `s`로 중단합니다. 오류는 원인을 해결한 뒤 `p`가 성공해야 다시 구동할 수 있습니다.

## 기존 코드와 다른 점

이 스케치는 모터를 **속도 제어 모드**로 바꿉니다. 자동으로 원래 위치로 돌아오지 않습니다. 종료 후에도 모드 설정은 남으므로 이전 각도 시험으로 돌아갈 때는 기존 위치 제어 스케치를 다시 업로드합니다.

이전 코드의 `GOAL_CURRENT=100mA` 설정은 속도 제어 모드의 같은 전류 제한으로 적용되지 않습니다. 이번에는 출력 제한과 전류 감시를 사용합니다. 모터가 돌지 않거나 오류가 나면 출력·속도를 바로 높이지 말고 전원·연결·메시지부터 확인합니다.
