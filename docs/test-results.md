# 시험 결과와 다음 기록

[README로 돌아가기](../README.md)

정리일: 2026년 10월 25일. 이 날짜는 모든 시험을 수행한 날짜라는 뜻은 아니다. 아래 결과는 실습 대화에 남은 출력, 작성자의 실제 동작 확인 보고, 업로드된 연결·통신 확인 사진을 바탕으로 정리했다.

“동작 확인”은 위에 적은 관찰 범위다. 예를 들어 자동으로 멈추는 것을 보았다는 사실만으로 정확한 복귀 각도나 토크 해제 응답까지 측정했다고 주장하지 않는다.

하드웨어 구성은 [보드와 두 모터의 연결 사진](media/wiring-two-motors-1.jpg)으로 기록했다. 정지 사진은 연결과 통신 확인의 근거로 사용하고, 움직임과 자동 종료는 동작 확인 보고와 앞으로 추가할 영상으로 구분해 기록한다.

## 다음 시험의 기록 순서

1. [기록 양식](../logs/test-session-template.txt)을 새 이름으로 복사한다. 예: `logs/session-2026-10-25-01.txt`. 실제 수행 날짜를 쓴다.
2. 운영체제, IDE, 보드 패키지, 라이브러리 버전을 기록한다.
3. 주 실행 프로그램에서 `p` → `1` → `2` → `b`를 하나씩 시험하고 전체 출력을 저장한다.
4. 각각 입력한 문자, 실제 움직인 모터, 자동 종료 여부를 적는다.
5. 별도 시험으로 `b`를 보낸 뒤 이동 구간에 `s`를 입력해 중단 결과를 남긴다.
6. 같은 조건의 위치 이동 시험을 3회 기록하고 성공·실패 횟수를 실제 결과대로 적는다. 3회는 앞으로 수행할 시험 계획이며 이미 완료한 횟수가 아니다.
7. USB를 분리했다 연결한 뒤 `p`로 주소 유지와 대기 상태를 확인한다.

## 판정 기준

| 시험 | 확인할 내용 |
| --- | --- |
| 통신 | ID 1·2에서 각각 모델 1200 응답 |
| 개별 제어 | 선택한 모터만 움직이고 반대쪽은 구동되지 않는지 |
| 함께 제어 | 두 모터의 움직임과 정상 종료 출력이 모두 관찰되는지 |
| 중단 | `s` 입력 후 취소 출력과 실제 구동 해제가 관찰되는지 |
| 위치 | 출력된 실제 변화량과 복귀 후 상태. 정확도를 주장하려면 별도 오차 측정 필요 |

부품·전원·각도·코드를 바꾸면 같은 조건의 반복으로 합산하지 않고 변경 내용을 따로 기록한다.
