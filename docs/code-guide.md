# 두 모터 코드 설명

[README로 돌아가기](../README.md)

대상은 [two_motor_usb_test.ino](../firmware/two_motor_usb_test/two_motor_usb_test.ino)다. 원래 구동 코드의 동작을 유지했으며, 이번 문서 정리에서 기능을 추가하지 않았다.

## 주요 설정

| 코드 | 의미 |
| --- | --- |
| `Dynamixel2Arduino dxl(Serial1, -1)` | OpenRB의 모터 통신용 객체 생성 |
| `MOTOR1_ID = 1`, `MOTOR2_ID = 2` | 명령을 보낼 모터 주소. 모터 내부 ID를 변경하는 명령은 아님 |
| `EXPECTED_MODEL = 1200` | XL330-M288-T의 예상 모델 번호 |
| `Serial.begin(115200)` | 컴퓨터와 시리얼 모니터 통신 설정 |
| `dxl.begin(57600)` | 보드와 모터 통신 설정 |
| `OP_CURRENT_BASED_POSITION` | 전류 설정을 적용하며 목표 위치로 움직이는 제어 모드 |
| `CURRENT_LIMIT_MA = 100` | `GOAL_CURRENT`에 쓰는 약 100mA 값. USB 전체 소비 전류를 보장하지 않음 |
| `MOVE_TICKS = 228` | 위치 이동 목표의 차이. `228 × 360 ÷ 4096 ≈ 20.04°` |

## 함수별 역할

| 함수 | 역할 |
| --- | --- |
| `setup()` | 통신을 초기화하고 두 모터에 토크 해제를 요청 |
| `loop()` | 안내 문구를 출력하고 문자 명령을 해당 동작으로 연결 |
| `showMotors()` | 두 ID에 Ping을 보내 응답과 모델 번호 출력 |
| `runTest()` | 선택한 모터의 준비·이동·복귀·종료 순서 수행 |
| `prepareMotor()` | 통신·모델 확인, 토크 해제, 모드·전류·속도 설정, 시작 위치 읽기 |
| `waitOrStop()` | 정해진 시간을 기다리면서 `s` 입력 확인 |
| `reportMovement()` | 이동 구간 뒤의 위치 차이를 읽고 각도로 환산해 출력 |
| `stopBoth()` | 두 모터의 토크 해제 요청 |
| `checked()` | 일부 통신·설정 실패 시 오류 출력과 토크 해제 시도 |

## 명령의 연결

```cpp
runTest(true, false);  // 1: 1번만 선택
runTest(false, true);  // 2: 2번만 선택
runTest(true, true);   // b: 두 모터 선택
```

개별 시험에서도 `runTest()` 시작 시 두 모터 모두 Ping에 응답해야 한다. 한 모터만 연결한 상태의 시험용 코드는 아니다.

선택한 모터에 대해 현재 위치를 읽고, 그 위치보다 228단위 큰 목표를 보낸다. 이후 원래 위치로 복귀 목표를 보낸 뒤 토크를 해제한다. 이 과정은 바퀴를 계속 굴리는 속도 제어와 구분된다.

## 현재 구현의 범위

- 이동·복귀 뒤에는 각각 정해진 시간을 기다린다. 목표 도달 오차를 반복 확인해 완료를 판정하는 기능은 없다.
- `b`는 두 모터에 순서대로 목표를 보낸다. 동기 쓰기 명령을 사용하는 정밀 동기 제어는 구현하지 않았다.
- `reportMovement()`가 읽는 것은 이동 구간 뒤의 위치 차이다. 복귀 후 잔여 오차나 반복 오차는 별도로 측정하지 않는다.
- `s`는 대기 구간과 명령 대기 중에 처리된다. 설정·통신 함수 실행 도중까지 즉시 응답하는 구조는 아니다.
- 시작·오류·중단 경로 일부의 `stopBoth()`는 토크 해제 요청의 성공을 개별 확인하지 않는다. 정상 종료 경로에서는 두 응답을 확인한다.
- `BUS_WATCHDOG = 0`은 해당 통신 감시 기능을 비활성화하는 설정이다. 통신 두절 시 자동 정지 기능을 완성했다고 설명하지 않는다.

위 항목은 다음 개선 때 비교할 기준이다. 현재 실제로 확인한 동작과 아직 확인하지 않은 항목은 [시험 결과](test-results.md)에 구분했다.
