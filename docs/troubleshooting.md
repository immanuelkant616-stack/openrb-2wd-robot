# 오류 해결 기록

[README로 돌아가기](../README.md)

실습 중 발생한 문제를 증상·판단 근거·대응으로 나누어 기록했다. 처음 추정했던 원인을 확정된 사실로 바꾸어 적지 않았다.

## 1. 보드·포트 인식 및 업로드

- **증상:** 포트가 보이지 않거나 `no upload port provided`, `No device found on ttyACM0` 등의 메시지가 나타났다.
- **점검:** USB 데이터 통신 가능 여부, 보드·포트 선택, 리셋 후 연결 상태를 확인했다.
- **대응:** 데이터 케이블 교체, 포트 재선택, 리셋·IDE 재시작 등을 거쳐 Blink 업로드와 모터 코드 업로드에 성공했다.
- **범위:** 충전 전용 케이블 사용은 초기 추정 원인 중 하나다. 각 조치가 어떤 오류를 단독으로 해결했는지에 대한 완전한 로그는 없다.

다시 발생하면 현재 보드명·포트명·업로드 전체 메시지를 먼저 기록한다. `/dev/ttyACM0`의 숫자가 항상 같다고 가정하지 않는다.

## 2. `reference to 'ID' is ambiguous`

컴파일러가 사용자 코드의 `ID`와 라이브러리의 `ControlTableItem::ID`를 구분하지 못했다.

문제가 있었던 이름의 예:

```cpp
const uint8_t ID = 1;
```

모터 주소 변수 이름을 구체적으로 바꾸어 해결했다.

```cpp
const uint8_t MOTOR_ID = 1;
```

두 모터 코드에서는 `MOTOR1_ID`, `MOTOR2_ID`를 사용한다. 변수 선언뿐 아니라 사용하는 곳도 함께 바꾸었다. 라이브러리의 제어 항목은 `ControlTableItem::...` 형태로 지정한다.

## 3. 새 명령을 보내도 이전 프로그램의 동작이 실행됨

ID 설정을 하려는데 `READY: type s...`가 반복되어 `s`를 보냈고, 모터가 잠깐 움직였다. 이 문구는 이전 한 모터 구동 코드의 안내였다.

IDE에서 새 파일을 여는 것만으로 보드의 프로그램은 바뀌지 않는다. 업로드 후 안내 문구로 현재 프로그램을 확인하도록 절차를 바꾸었다. `✓`는 컴파일 검증이고, `→`가 보드 업로드다.

| 시리얼 안내 문구 | 의미 |
| --- | --- |
| `READY: type s...` | 이전 한 모터 구동 프로그램. 여기서 `s`는 시작 명령이었음 |
| `ID SETUP: second motor ONLY...` | 이 저장소에 포함된 단일 모터용 ID 설정 도구 |
| `ID SETUP \| p: inspect \| t: first 1->10...` | 당시 검토한 임시 ID 변경 도구. 이번 저장소의 실행 대상에는 포함하지 않음 |
| `READY \| p: check IDs \| 1: motor 1...` | 현재 두 모터 위치 이동 시험 프로그램 |

프로그램마다 같은 문자의 의미가 다를 수 있다. 시리얼 모니터 속도는 115200 baud로 맞춘다.

## 4. 모터 ID와 코드 변수명의 혼동

`MOTOR_ID`는 코드에서 사용하는 이름이고, `1`은 그 이름에 저장한 숫자다. 모터 내부의 통신 주소를 변경하려면 별도의 `setID()` 명령이 필요하다.

두 모터를 연결한 상태에서 최종적으로 다음 응답을 확인했다.

```text
FOUND: ID=1 Model=1200
FOUND: ID=2 Model=1200
```

이 결과를 확인한 뒤에는 ID를 다시 바꾸지 않고 두 모터 구동 코드로 전환했다. 원문은 [검색 로그](../logs/id-scan-observed.txt)에 보관했다. 실제 ID 변경 명령의 전체 실행 순서는 기록이 부족하므로 재구성해 주장하지 않는다.

## 5. 커넥터가 잘 빠지지 않음

첫 번째 모터 커넥터가 뻑뻑해 분리가 어려웠다. 전원을 끄고 플러그 몸통을 잡는 방법과, 첫 모터의 ID를 임시로 바꾼 뒤 두 번째 모터를 추가하는 대안을 검토했다.

임시 ID 10을 거치는 방식은 안내된 대안이다. 실제 완료한 절차로 기록하지 않는다. 같은 ID인 두 모터를 소프트웨어 검색만으로 구분할 수 있다고 가정하지 않는다.
